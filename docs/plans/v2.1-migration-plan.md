## 迁移策略原则（重要：V1 已废弃）

- **V1（`E:/08-Codework/Intelligence-Hub`）已不再维护、不再需要**：迁移时可直接搬运/覆盖 V1 代码，无须保留 V1 可运行性，也无须为「V1 还在用」留兼容。V1 工作区一行不动只是归档需要，不是约束。
- **默认策略 = 搬运**：每个任务标注 `策略:搬运 / 重构 / 适配`：
  - `搬运`：直接拷 V1 代码到 V2 对应位置，最小改动让它 import 通；**文件顶部显式加 `# TODO(v2-adapt): 未适配，直接搬运自 V1，未来按 V2 范式重构`**。未来需要时再适配。
  - `重构`：必须改结构（如统一三份 postprocess、React 重写原生 JS 工坊），不能纯搬。
  - `适配`：核心搬 V1，但接入层（接入 TaskRunner / PlatformAdapter 契约）需新写薄层。
- **未适配约定**：搬运但未适配的模块，文件顶部加上述 TODO 注释 + 在本计划任务行尾标 `未适配`；**不强制接入 V2 主流程调用**（避免引入未适配的副作用），仅作为可被显式调用的能力存在。
- **仅当「会阻塞 V2 运行或破坏契约测试」时才做适配**，否则先搬后补。
- **飞书全家（T5.1）与分析层引擎（T5.2/T5.3/T5.4）按用户决定**：先直接搬 V1 代码、标 `未适配`，保留 V1 原结构（含独立镜像库、PipelineLock、lark-cli 子进程封装、纯本地算法），未来需要时再适配。
- **批量搬运可并行**：`策略:搬运` 的任务彼此独立、无契约改动，可由一个 Agent 批量扫一批搬一批（见 §策略总览）。
