# ADR-0024: 「截图包」是成片的派生物：走端点同步截，不入库、不起任务

- **状态**：Accepted
- **日期**：2026-09-25
- **决策人**：用户 + Qoder
- **相关**：ADR-0018（搬运区：V1 的截图那一路没搬进来）、ADR-0021（topics/drafts 两张表）、
  `docs/plans/v2.1-migration-plan.md` T4.7 / T6.7、`docs/specs/data-model.md §2.3`（`media_path`）、
  `docs/specs/api.md`（若存在）与 `docs/specs/openapi-snapshot.json`

## 背景

创作工坊第四格「截图包」（T4.7 落地时它说的是一句实话："V2 没有这一步"）在 V1 里是真的：
V1 有一条按分镜截截图的任务，产物进飞书。V2 的媒体只有一件事 —— `videos.media_path`
指的**成片**。要把那一格补成真数据源，必须先回答三个问题，而它们各自的默认答案都不对：

1. 帧从哪来？（没有分镜图，只有成片）
2. 要不要进库？（"上次截了哪些帧"看起来该记一笔）
3. 要不要做成任务？（仓库里凡是耗时动作都走 `TaskDefinition`，界面也就有了进度条的形状）

另外还有一条外部约束：`data/` 底下躺着 `cookies/`（有效会话凭证）与 CDP profile（登录态），
而这是一个**无鉴权的回环端点**，要按用户的输入去读磁盘。

## 决定

### 一、产物是派生物，一律不入库

`POST /api/videos/{id}/shots` 用 ffmpeg 从**这条作品已落地的成片**里按时间点截帧，
文件落在 `<媒体目录>/shots/shot-<秒>.jpg`，**不加列、不加表、不做迁移**。

判据是"能不能再生"：帧完全由 `media_path` + 时间点决定，删了重截等价。
记一份"上次截了哪些帧"就是**第二个真源**，而 V1 §7.7 那一族（双源）正是这么来的 ——
一旦那份记录和磁盘不一致，症状会是"界面说有图，点开是 404"，
比"根本没有这一格"更难查。"有没有截过"这件事由磁盘自己回答：
命名对时间点**单射且确定**（`FileStorage.shot_file`），所以 `cached` 不需要记账也算得准。

### 二、同步做完，不起任务

截 12 帧是秒级的事。任务化的代价不是排队，是**界面语义**：任务队列表达的是
"稍后会有人来收拾"，而这一格要的是"点了就看见"。一旦任务化，
组件就得先长出"进行中/排队中/部分成功"三态，而那三态今天在 `runs` 那一页已经有完整表达 ——
把同一个动作塞进两个地方各表达一遍，正是本仓库反复躲开的那种重复。

### 三、`POST` 而不是 `GET`

这个动作往磁盘写字节，而副作用必须由用户点出来。`GET` 在 HTTP 语义里必须安全，
一个会被爬虫、预取、浏览器历史补查打中的写盘端点，等于"没人点也在那儿截帧"。

### 四、出图那三层边界，以及它们各自挡什么

`GET /api/videos/{id}/shots/{name}` 三层：① 名字必须是个**单纯的文件名**
（正则挡 `/`、`\`、NUL、结尾点号）；② 扩展名必须在图片白名单里；
③ 解析后仍必须落在**这条作品自己的** `shots/` 底下。

目录**不是参数**，是从库里的 `media_path` 反推的 —— 这一条比 `media.py` 更紧，
它让"换到别人的作品上"这件事在 URL 里没有表达位置。

三层不是平均用力的：①是入口闸门，③今天从 HTTP 打不到（任何带分隔符的名字在①就死了），
它是"哪天有人放宽①"时唯一还在的那道。这句话必须写下来，因为
**第一版给③写了一条走 transport 的用例，而那条是空转的**：诱饵按猜的目录名埋
（真目录名带作品 id 前缀），payload 在磁盘上指向不存在的路径，把三层全拆掉它照样绿。
现在那两条各归各位：①②③的组合用**由实际相对路径派生**的 payload 测（拆①+③会红），
③自己用一条直接测 `_is_under` 的用例测（改坏函数体会红）。

## 后果

- **`shots/` 住成目录里面**，所以删作品、搬媒体都不会留孤儿；`media.py` 那两条
  "只认 `media_root` 底下 + 扩展名白名单"的判据天然罩得住它。
- **`cached` 与磁盘重扫（T4.4）会互相看不见**：媒体被移走后旧帧的归属今天没测，
  记在 `docs/progress/2026-09-25.md` 的未验证清单里。
- **前端不拼路径**：网格里的 `<img src>` 只用后端给的 `url`。在前端算磁盘路径等于
  把目录结构写进第二处（V1 §7.5 那一族）。
- **这台机器有没有 ffmpeg 是个会被误诊的问题**：`where ffmpeg` 打不出来而二进制确实装在
  WinGet 目录里（V1 §7.19 那个"注册表有、进程 PATH 没有"的形状）。所以这一族的验证
  分两条：文件语义吃假 seam（`test_api_shots.py`，36 条），真二进制那一头另有一条
  `-m real_network`（`test_shots_real_ffmpeg.py`，先 `prepare_runtime_environment()` 补 PATH
  再验"同一秒两次一致、不同秒必须不同字节"）。**别把前者当成"验过画面了"**。
- 工坊那一格的"没有成片就一句实话"保留，但判据从"组件里写死"换成了 `media_path`
  （`lib/workshop.ts::canRequestShots`）：这一格从此与其它格同构，输入缺失在点之前就说得出。
