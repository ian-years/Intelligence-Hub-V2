# ADR-0023：暗色版换的是**角色**，不是色号 —— 三个中性色令牌在 `[data-theme="dark"]` 下重新指派

日期：2026-09-25 · 状态：已接受 · 相关：`docs/specs/ui-tokens.md §2.5 §11`、ADR-0013（tokens.css 是唯一真源）、T5.6

## 背景

`ui-tokens.md §11` 在 V2.0 就把暗色版留成了四行草稿（背景换 `#1A1A1A`、文字与描边换
`paper_cream`、主色保持亮色、走 `[data-theme]` 切换）。T5.6 实施时撞上两件草稿没写的：

1. 全站 400 多处引用的是**色号名**（`bg-paper-cream` / `border-ink-black` / `text-ink-black`），
   不是角色名（surface / line）。孟菲斯的描边、硬阴影、正文三者共用同一个 `ink_black`。
2. "主色保持亮色"与"正文色翻成浅色"叠在一起时，**色块上的字**（`bg-coral-red` 里面那段话）
   会跟着正文一起翻，得到"亮块 + 亮字"。

## 决定

- **在 `[data-theme="dark"]` 里重新指派三个中性色令牌的角色**：
  `paper-cream` → 面（`#1A1A1A`）、`ink-black` → 线与正文（`#FAF7F2`）、`grey-mist` → 次级底（`#3D3D47`）。
  组件与 `globals.css` 的引用**一处不改**。
- 新增 §2.5 `--color-on-accent`（两版都是近黑）：五个主色继续当亮块，块上的字走这一条。
  `electric-blue` 例外（它压不住近黑字，只有 4.1:1），它的配字是 `paper-cream`，
  由 `tokens.spec.ts` 扫源码钉住"每处 `bg-electric-blue` 必须带 `text-paper-cream`"。
- `electric-blue` 在暗色下调亮成 `#4D9BFF`：它是五个主色里唯一被当**文字**用过的
  （链接），`#0066FF` 压在 `#1A1A1A` 上 3.6:1，过不了 4.5。
- `data-theme` 只写 `light` / `dark`；界面上的第三档"跟随系统"在写 DOM 前解析完，
  写点唯一（`Layout.tsx`），且订阅 `matchMedia` 的 change 事件。
- 两版每一对角色色的对比度**由测试量**（WCAG 2.1 公式在 `tokens.spec.ts` 里实现），
  并且扫 `src/**/*.tsx` 把"真被当正文色用的色"逐个压在页面底上量一遍。

## 备选与代价

| 方案 | 为什么没选 |
|---|---|
| 新设 `--color-surface` / `--color-line` / `--color-on-surface`，组件改成引角色名 | 概念最干净，但要改 400 多处调用点。**漏改的那一处不会报错、也不会被任何测试发现**，症状正是"暗色下某个角落还是白的"。改三个令牌则是"要么全站一起变、要么当场红" |
| 每个组件写暗色变体（`dark:bg-…`） | 同一件事 43 个出处，且把配色决策散落到组件里；ADR-0013 的"令牌是唯一真源"直接失效 |
| 只换背景与文字、`grey-mist` 不动（照 §11 字面） | 实测次级底留在 `#D8D8D8` 上压浅色正文只有 1.3:1，比不换还差 |
| 主色整体调暗以保住"正文色当块上的字" | 那就不是孟菲斯了（§1：高饱和撞色块 + 粗黑边 + 硬阴影） |
| 首屏默认亮色，"跟随系统"只做两档 | 与 §11 的"切换"承诺不冲突，但用户系统已经是暗色时会先被亮色闪一次；`system` 作为默认值的代价只是多一个解析函数 |

## 后果

- **名字与色相在暗色下故意对不上**（`paper-cream` 是深色，`ink-black` 是浅色）。这是本决定
  唯一需要人记住的反直觉之处，写在 §11 开头与 `tokens.css` 那块注释里；令牌名属于
  V3 冻结契约（§12），不改名是刻意的。
- `tokens.json` 仍是 `@theme` 的投影，**不含暗色块**：JS 侧只用到动效时长与平台显示名，
  一处颜色都不读（`lib/tokens.ts` 的消费方实测只有 `DURATION` / `EASING` / `PLATFORM_NAMES`）。
  将来若有人在 canvas/SVG 里画色块，那时再决定要不要把暗色一起投影出去。
- `color-scheme` 跟着换，否则暗色页面里会浮出浏览器自己的白色下拉框与滚动条。
- 未验证：**真机像素层面的观感**（图案层 `patterns.css` 在深色底上的对比、
  13 档间距下色块的视觉重量）。这一层要的是 Playwright 视觉回归基线，
  计划里就标在待办池（T5.6 验收句的"视觉回归基线（待办池）"）。本 ADR 的数都是算出来的，
  不是量屏的。
