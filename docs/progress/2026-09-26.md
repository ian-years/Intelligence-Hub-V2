## 9. `BackfillTask` 的设计定稿（**同一天的 §11 已经照这一节做完了**，留着是为了看"决定是在动手前做的"）

读过的现成形状（不是照印象设计的）：`tasks/collect.py:102` 的 `_resolve_targets`
（`creator_ids` 给定就 `get_or_raise`，否则 `list_tracked`）、`collect.py:140` 的
`_collect_one_video`（查重 → 下载 → 入库 → publish 快照，一整套失败语义都在里面）、
`storage/repositories/creators.py:79` 的 `list_tracked` docstring —— 它**早就写明**
"按位任务不走这里，用 `find()` / `get_or_raise()`"。所以 §7.22 的存储层那一半已经存在，
缺的是任务层那一半：`backfill` 从来没有 handler。

四个定稿，每个都带理由：

1. **参数：`creator_url` 必填**（+ `top: int = 5`、`scan: int | None = None`）。
   不是 `creator_id` —— `docs/specs/task-runner.md §457` 与 ADR-0005 写的就是
   "`creator_url` 必填，走 `parse_creator_url` 直接定位"，那是 V2 对 V1 事故的契约化，别改。
   界面上那位博主有 `profile_url`，传它就行；`scan` 不给时取 `config.videos_per_creator`
   的一个显式倍数（**扫描窗口 ≠ 交付条数**，这件事必须能在 summary 里看出来）。
2. **点名一位库里没有的博主 → 如实失败**，文案给出可粘贴的 `add_creator` 参数；
   **不**自动建行、**不**退化成全库扫描。理由：建行要顺带决定"跟踪开关开不开"，
   而 §7.24 说那个开关只有用户能碰；回溯的入口在博主卡上，正常路径永远命中已有行。
3. **排序**：`like_count` 降序，`None` 一律排在最后并单独计数
   （`summary["unknown_metrics"]`）。把"不知道"当 0 参与排序，等于让一条读数缺失的
   旧作品冒充爆款 —— 那是这份判据最不该给的绿。
4. **复用而不是复刻**：逐条下载走 `collect._collect_one_video` 与 `_Tally`。
   再写一份"查重+下载+入库"就是 §7.11 那一族（collect.py 的模块 docstring 自己就反对这个）。

要改的六处（一条不落，否则就是文档说谎）：
`tasks/params.py`（新 `BackfillParams`）→ `tasks/backfill.py`（新 handler）→
`tasks/dispatch.py`（绑 handler）→ `core/task_registry.py:208`（`implemented=True` +
`platforms=()`：这个任务吃的是 URL，哪家都能吃，所以**不能**列四家 —— 列了就会
"关掉一家，另三家的回溯按钮也没了"）→ 前端 Creators 页那一枚按钮（**参数从 `profile_url` 来**，
判据沿用 Tasks 页那套"能不能一键发起由 `params_schema.required` 决定"）→
契约面三处同改：`docs/specs/task-runner.md`、`AGENTS.md §5` 那一栏、
`tests/contracts/test_contract_guard_index.py`，用例名按 ADR-0009 已经指定的那个：
`test_backfill_task_uses_creator_url_not_full_scan`。

测试要挡住的五种红（先写它们再写实现）：库里没有 → failed 且 `list_creator_videos` **一次都没被调用**；
跟踪开关关着 → 仍能定位到那位（这一条就是 §7.22 的本体）；URL 认不出 mid → 红在文案而不是扫全库；
`scan=30 / top=5` → 落库恰好 5 条且 summary 里 `scanned=30`；
`like_count` 全 None → 不崩、`unknown_metrics=30`、且交付的不是"随便前 5 条"。

### 11.2 顺手挖出来的两个 PUT 缺陷（未修，等点头）

   写盘把内存里的**默认值**物化进了文件，于是"配了但没人读"从注释变成看起来像用户配的。
3. 95 行注释 → 0 行：这一条**不是缺陷**，文件头上就写着"这些注释活不过第一次 PUT"。

修法各自是什么、要不要现在做，见 §12 第 35 行。**没有回退那份 config**：
