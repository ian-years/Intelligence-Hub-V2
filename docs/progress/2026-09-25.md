2. **e2e 发现了一个真缺陷**：`useRuns` 只在提交那一刻 invalidate 一次，于是"实时事件在滚、
   运行历史永远停在正在跑"。修成"有 running 就轮询"（`useTasks.ts`），并留了一条 e2e 钉它。
3. **构建产物过期会让 e2e 红得没有道理**：改完 `useRuns` 那两条 e2e 红，原因是 dist 是旧的。
   `dist_dir` fixture 从此**每次**都 `npm run build`。
4. **e2e 与 pytest-asyncio 抢事件循环 policy**：裸跑 `pytest` 会让之后每条 async 用例报
   "Cannot run the event loop while another loop is running"（实测 1604 errors）。

   而不是指望测试之间"互相不打扰"。

   服务端 fallback 是**没有问题的预防**。第一版加了 `_SpaStaticFiles` + 4 条用例，
   查清路由形态之后整块撤掉 —— 留下它，`make e2e` 里那三条就会因为"任务页找不到按钮"而红，
   因为地址得写成 `/#/tasks`。

### 8.1 T4.1 / T4.2 调用侧（`44e205b`）

`publish` 快照接上。三档回答值得单独记，因为**档位差就是要被看见的东西**：

| 家 | 评论 | 读数 | 做不到时怎么说 |
|---|---|---|---|
| B站 | 真做（`x/v2/reply`，先问 `view` 拿 `aid`） | 真做（`view` 的 `stat` 四项） | — |
| 小红书 | None（签名接口没实现） | 只有 `likes` 一项，其余 NULL | 抛并说"页面形状变了，不是零互动" |

实现期被用例逼出来的三处修正（都不在原计划里，都不是"实现细节"而是判据）：

1. **frozen+slots dataclass 的默认值顺序**：`supports_comments: bool = False` 插在中间，
   报的是 `non-default argument follows default argument` —— 与平台无关、与顺序有关，
   第一反应会以为是声明写错。新能力位一律往**末尾**加（已写进 `platform-adapter.md §2.2`）。
2. **库里有一条 B站 作品、而这一家今天没装配** → 原先整轮崩在 `adapters.get()`，
   现在记一条 `metrics` 失败照常收尾。这是"关掉平台再跑补抓"的形状。
3. **`compact_number_to_int` 对"有字但不是数"抛 ValueError** → 裸错没有平台名与 stage，
   换 `PlatformError` 并照抄原文。顺带把两种坏法分开报（"不是个数" vs "读不出来"）。

一条通用契约**没有**进基类，理由是量的：`fetch_metrics` 不许交回空读数这一条，

### 8.2 那个副作用怎么没的（`3027246`）

上一轮为了让裸 `pytest` 不被 e2e 污染，我在 `addopts` 里加了一条 `-m "not ... and not e2e"`。
那是在**遮盖症状**。根因用三条探测量出来：`sync_playwright` 会在主线程 asyncio 的
"当前运行循环" ContextVar 里留一个**活但不在跑**的循环，于是之后每一次
`asyncio.run()` / `Runner.run()` 都报 `cannot be called from a running event loop`
（policy 与 `policy._local._loop` 都是干净的 —— 三个猜测方案全被实测否掉）。

正解是**不引入第二个循环主人**：`tests/e2e/` 换 `playwright.async_api`，
跑在 pytest-asyncio 自己那个循环上，浏览器改成函数级。然后
`addopts` 里那条 `-m` 排除**整块删掉**。数字：`pytest tests/e2e tests/integration`
同一进程 228 passed / 0 errors（此前是 161 failed + 1604 errors）。

### 8.3 截图包有了真数据源

新端点一族（`api/v1/shots.py`）：`POST /api/videos/{id}/shots` 用 ffmpeg 从成片现截，
`GET .../shots/{name}` 出图。产物**不入库**（可再生的派生物，记一份"上次截了哪些帧"
就是第二个真源），同步做完不起任务（秒级动作塞进任务队列只会把界面变成"不知道在等什么"），
写盘动作必须是 `POST`。三条判据都记进了 ADR-0024。

**这条链上发现的一个真 bug**：`tests/e2e/conftest._stub_adapter` 造的产物写的是
`media_source="e2e_stub"`，而 `MediaSource` 那四个字面量里没有它 —— 也就是
**e2e 里从来没有一条用例真的走到过 `download_media`**，所以它一直没人发现。
新加的那条长链一跑就炸出来（症状是"采集 failed + 两条 download 失败"）。

**一条空转用例被修掉**（这是本轮最值得记的流程教训，进 lessons）：
出图端点那条"越界一律拒"，诱饵是按**猜的目录名**埋的（真目录名带作品 id 前缀），
payload 在磁盘上指向一个不存在的路径 —— 把三道判据全拆掉它照样绿。
更险的是它的 docstring 写着"变异验证：把 `_is_under` 改坏，这一条会红"，而那句是假的。
修完的形状：payload 由 `os.path.relpath(诱饵, shots_dir)` **现算**，
前面加一段"这两个相对路径确实指到诱饵上"的防空转前置，再加一条
"至少 N 条写法真的打到了应用层"的看护（否则客户端归一化会把覆盖面静默吃掉）。
变异实测：拆①+③ → 红（那张 `.jpg` 真被交出去）；只拆① → 绿（③接住，证明它不是死代码）；
只拆③ → 绿（①本来就挡完，所以③另有一条直接测函数的用例）。

**两次我自己的假阴性**，都要记：
① 第一次跑变异 harness 时 `s.replace(anchor, ...)` 的锚点用了单引号而源码是双引号，
替换根本没生效，我却据此下了"这条用例挡不住"的结论 —— 从那以后 harness 里每一次
替换都 `assert old in text`。② 报"这台机器没有 ffmpeg"（`where ffmpeg` 为空）也是误诊：
二进制装在 WinGet 目录里，只是进程 PATH 的快照里没有 —— 正是 V1 §7.19 那一族。
补 PATH 之后真机验证跑通了（§8.4）。
