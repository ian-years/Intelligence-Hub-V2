### 与设计文档的偏差（都是 spec 那边不成立，不是实现偷懒）

1. `FileStorage.transcript_path(media_dir)` 而不是计划的 `(video_id)`
   —— 稿子与媒体同住一个目录（Locked 的 `data/` 布局），只有先算出媒体目录才能算出稿子路径。
2. `attach_transcript()` 返回 `TranscriptRecord` 而不是 `Transcript`
   —— `Transcript.text` 是必填，而正文按 §2.4 只在磁盘上。**已回写 `data-model.md §3`**。
3. 没有 `InMemoryStorage` 类，只有 `SqliteStorage.in_memory()` —— 差别只有 URL 与建表方式两处，
   复制一份等于复制漂移可能性。**已回写 `data-model.md §4`**。
4. 全局事件（`platform.health_changed` / `config.changed`）**只广播不落库**
   —— `task_events.task_id` 是 NOT NULL（§2.6 Locked）。放宽它更糟：
   与任务无关的事件会被硬挂到某个任务上，任务详情页日志里出现不属于它的行。
   **已回写 `event-schema.md §4`**，`prune()` 的三条口径同时补进 §6。
5. 新增 `StorageError` 之下的 `NotFoundError` / `ConflictError` / `MigrationError`（Task 1 没有）。
6. 行类型比 spec 多：`TaskRunRecord` / `StoredEvent` / `ManifestRecord` / `PlatformRecord`
   —— "采集层的产出"与"存储层的行"不是一个东西，混用会造出 `text=""` 这种假对象。
7. `task_runs` 多一条 `terminal_has_ended_at` CHECK（V1 §2 契约二在 DB 层的落点，spec 里没写）。
8. `SqliteStorage.initialize()` 里迁移用 `asyncio.to_thread` 包（同步 alembic 在事件循环里跑会炸）。

### 顺手修的两处非 Task 3 范围

- `ruff` 的 `TC002` 与已豁免的 `TC001/TC003` 是同一条理由的另一半，漏掉它得到
  "同一个仓库一半文件把 import 挪进 TYPE_CHECKING、一半不挪"。补上并把理由写全，
  同时明确**别读成"TYPE_CHECKING 被禁了"**（`storage` 的两处是分层要求，照旧手写）。
- 删掉 Task 1 骨架留的两个空占位 `storage/migrations/.gitkeep` 与
  `storage/repositories/.gitkeep`。前者尤其该删：迁移在仓库根 `alembic/`（ADR 0006 定的位置），
  包内再留一个 `migrations/` 空目录，下一个人会以为是两处、要猜哪一处是真的。
- 新增 `.gitattributes`（`* text=auto eol=lf` + 二进制名单）。起因是本机
  `core.autocrlf=true` 且仓库里没这份文件，于是 checkout 出的 `.py` 是 CRLF，
  而 `pyproject.toml` 写的是 `line-ending = "lf"`。**实测**（把一个逐字相同的
  `session.py` 复制成 CRLF 版再问 ruff）：`ruff format --check` → exit 1、
  整份 diff 只有行尾；`ruff check` → All checks passed。
  也就是**只有 format 那关会被行尾打爆，且只在 Windows 上** ——
  CI 是 Linux，会一路绿，本地 `make ci-local` 报几百个假红。
  这种"本地与 CI 结论相反"的门禁比没有门禁更糟，所以让仓库自己定行尾。
  **CI 里要补 `ruff format --check`（Task 16）**，否则这份 `.gitattributes` 只是防御性存在。
