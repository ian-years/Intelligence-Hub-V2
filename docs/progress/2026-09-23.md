### 事件时序：清单先写盘，再广播 `task.finished`

`TaskRunner.execute` 把终态生命周期事件放在 `async with manifest_writer(...)` **出块之后**发。
顺序是 `task.started → manifest.written → task.finished`（看护在
`test_success_writes_terminal_run_and_events`）。反过来会得到"前端收到完成事件、点进去清单 404" ——
清单是权威源，它必须先于"我完成了"这条广播落盘。

### 这一轮抓到的一个真 bug：热重载后"关掉的平台照样能被采"

`PlatformRegistry` / `DepsFactory` / `TaskScheduler` 三处各自缓存了一份 `configs` 快照用于门控与装配。
`PUT /platforms/{name}/config` 走 `reload_platform()` 只更新了 `ConfigManager` 自己那份内存 ——
结果 `/api/tasks` 看着平台被关了（它读 manager），但 `scheduler._gate` / `registry.enabled_platforms()`
还看着旧值，**关掉的抖音照样能被 `douyin_collect` 采**。修法：
`AppState.apply_platform_config(name, cfg)` 一次把新配置推到三处 + `registry.invalidate`；
`reload_platform` 的订阅者（lifespan 注册）与 PUT 路由都走它。看护
`test_put_config_persists_and_gates`（断言关掉后 `douyin_collect` 从 `/api/tasks` 消失
**且** `scheduler._configs["douyin"].enabled is False` —— 只断言前者会漏掉真正的门控那份）。

### 两处实施期决定（都记进 `docs/lessons.md`）

- **SSE 生成器：先 `subscribe` 再 `replay`**（`api/v1/events.py`）。原写法（replay 在前）有个
  `finally` 引用未绑定 `subscription` 的洞：消费者在 replay 阶段就 `aclose()` 会 `NameError`。
  改成 subscribe 先行后 `finally` 一定拿得到订阅句柄，顺带补上"追历史时刚好跑完"那条 live 事件。
- **API 测试不跑真 lifespan**（`tests/integration/conftest.py`）：这版 starlette 的 `TestClient`
  依赖未装的 `httpx2`、且 `from fastapi.testclient import TestClient` 一 import 就发弃用告警，
  撞 `filterwarnings=["error"]` 直接红。改成 fixture 手动 `storage.initialize()` + 预置镜像行 +
  `httpx.ASGITransport` 打路由；lifespan 的真装配单独用 `test_app_lifespan`（直接测
  `build_components` + `_sync_platform_mirror`）覆盖。写配置的用例走 **tmp 目录**那份
  `platforms.yaml`，绝不改仓库 `config/`。

### 这一轮的一个判断：为什么"加基类"而不是"改造两套大测试去继承"

计划文件 line 466 说"Task 14 抽基类时把这 91 条里通用的部分上移"。真做时发现：上移 = 把两套
各自已经绿的大测试拆开重接，任一拼错就是几百条红，而且**上移后断言的内容一个字没多**（通用契约
本来就在两套里各写了一份）。所以选了**加一份可复用基类 + 让两平台各自实例化真适配器过一遍**：
既拿到"V3 继承即得"的可复用资产（基类是交付物），又不动正在绿的 200+ 条。代价：通用契约目前在
基类与两套大测试里各有一份（重复），但重复的是**测试**不是行为真源，且索引看护盯着它们存在。
这条决定记进 `docs/lessons.md` 经验 22。
