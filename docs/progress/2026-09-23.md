### 事件时序：清单先写盘，再广播 `task.finished`

`TaskRunner.execute` 把终态生命周期事件放在 `async with manifest_writer(...)` **出块之后**发。

`test_success_writes_terminal_run_and_events`）。反过来会得到"前端收到完成事件、点进去清单 404" ——
清单是权威源，它必须先于"我完成了"这条广播落盘。

### 这一轮抓到的一个真 bug：热重载后"关掉的平台照样能被采"

`PlatformRegistry` / `DepsFactory` / `TaskScheduler` 三处各自缓存了一份 `configs` 快照用于门控与装配。
`PUT /platforms/{name}/config` 走 `reload_platform()` 只更新了 `ConfigManager` 自己那份内存 ——
结果 `/api/tasks` 看着平台被关了（它读 manager），但 `scheduler._gate` / `registry.enabled_platforms()`
还看着旧值，**关掉的抖音照样能被 `douyin_collect` 采**。修法：
`AppState.apply_platform_config(name, cfg)` 一次把新配置推到三处 + `registry.invalidate`；
`reload_platform` 的订阅者（lifespan 注册）与 PUT 路由都走它。看护
`test_put_config_persists_and_gates`（断言关掉后 `douyin_collect` 从 `/api/tasks` 消失
**且** `scheduler._configs["douyin"].enabled is False` —— 只断言前者会漏掉真正的门控那份）。

### 两处实施期决定（都记进 `docs/lessons.md`）

- **SSE 生成器：先 `subscribe` 再 `replay`**（`api/v1/events.py`）。原写法（replay 在前）有个
  `finally` 引用未绑定 `subscription` 的洞：消费者在 replay 阶段就 `aclose()` 会 `NameError`。
  改成 subscribe 先行后 `finally` 一定拿得到订阅句柄，顺带补上"追历史时刚好跑完"那条 live 事件。
- **API 测试不跑真 lifespan**（`tests/integration/conftest.py`）：这版 starlette 的 `TestClient`
  依赖未装的 `httpx2`、且 `from fastapi.testclient import TestClient` 一 import 就发弃用告警，
  撞 `filterwarnings=["error"]` 直接红。改成 fixture 手动 `storage.initialize()` + 预置镜像行 +
  `httpx.ASGITransport` 打路由；lifespan 的真装配单独用 `test_app_lifespan`（直接测
  `build_components` + `_sync_platform_mirror`）覆盖。写配置的用例走 **tmp 目录**那份
  `platforms.yaml`，绝不改仓库 `config/`。

## 审查轮 第三组 · 死配置字段（ADR-0012）+ `_check_requires` 的"先别做" — ✅（字段）/ ⏸（requires）

### 那 6 个字段量出来是 14 个

上一轮写"6 个"是手数的。真正遍历 `PLATFORM_CONFIG_SCHEMAS` 到叶子字段、逐字段找读取路径之后：
**douyin 7 个 + bilibili 7 个**。表、判据、以及每一条"实现它的正确形状"都在
[`docs/adr/0012`](../adr/0012-unread-config-fields-marked-ui-hidden.md)。

修法选了**标 `ui:hidden` + `Field(description=...)` 写明实际生效规则**，不是删、也不是记账：

- **不删**：这些模型是 `extra="forbid"`，而仓库自己那份 `config/platforms.yaml` 里这 14 个键全在，
  每次启动都要过校验。现场量了给 `DouyinAdvanced` 多喂一个键的报错：
  `extra_forbidden` / `Extra inputs are not permitted` —— 删字段就是让这份 yaml 走同一条路，
  症状从"表单上一个空开关"变成"升级后服务起不来"。
- **不记账**：第一版真的写成了一个 `KNOWN_DEAD_FIELDS` 名单，随即否掉 ——
  撒谎的位置是**已发布的 API**（`/api/platforms/{name}/schema` 今天就在吐这些字段），
  名单躺在测试文件里等于把真相放在只有守卫看得见的地方。

看护是 `tests/unit/platforms/test_config_fields_have_readers.py` 四条，构成**双向**棘轮：
新增没人读的字段 → 红；字段被实现了却还留着隐藏 → 也红（否则隐藏变成只进不出的抽屉）。

### 量这个过程中撞出来的三件事（比名单本身贵）

1. **守卫差点是假的**：`_SRC` 层级写成 `parents[2]` 指进了 `tests/`，语料为空 → 全部字段被判死。
2. **散文能满足判据**：`bilibili/listing.py` 的**模块 docstring** 里那句
   「走哪条由 `capabilities.list_strategy` 与配置决定」让 `bilibili.list_strategy` 躲过了检测 ——
   而 `_enumerate` 实际按 `external_browser_manifest_path` 给没给选路，**一行都没读那个字段**。
   判据因此改成 AST（剥掉 docstring 与注释再匹配属性访问）。→ 经验 32。
3. **子类重新声明会静默丢掉父类的 `json_schema_extra` 与 `description`**（实测
   `C.model_fields[k].json_schema_extra is None`）：所以"基类标一次四个平台都生效"不成立，
   标记必须打在重新声明处。→ 经验 33。

顺手量到一条同形状的欠账：`config-schema.md §4` 说前端按 `ui:advanced` 折叠高级字段，
而**全仓库没有任何一处标过它**（唯一用到 `json_schema_extra` 的地方是 `ui:order`）。
现在它真的在 schema 里了，并有独立断言盯着。`§3.2` 那个代码块里还留着 ADR-0011
说"已删除"的 `cookie_variant_order` 与 `list_strategy: 'api'` —— 注记说删了、示例还在
就是第二处真相，一并对齐。

### `_check_requires`：量完之后决定这轮不做

上一轮列的第 2 项之一。量出来的事实：

- 6 个 V2.0 handler 的 `requires` 里，**已经没有任何"声明了但没人检查"的东西** ——
  `postprocess.requires` 就是 `()` 并带注释说明为什么（不是假的 `("asr",)`）。
- 真会红的那些 token 是 `cdp_bridge` 与 `cookies:*`，而判断这两样的唯一诚实手段是
  问一次 `adapter.healthcheck()` —— 那是**提交任务路径上的一次网络调用**。
  V1 §7.23 的教训正是"用时抖动门禁"，所以要做对就得先有一个**缓存的能力快照**
  （preflight 结果 + TTL + 失效点），那是一个设计决定，不是一行 `if`。
- 半做的形状恰好是我们花两轮在拆的那种东西：声明了、看起来在查、实际不生效。

所以这里**不是漏掉**，是记在 ADR 之前的一个待定设计。要动它就先写一篇 ADR
（快照的生命周期、谁负责失效、红的时候是拒绝提交还是降级排队）。
编号 0013 已被设计令牌那条占用，这条落地时用 ADR-0014。

**门禁现状**：`1308 passed`、覆盖率 `93.99%`、`tools/migrate_from_v1.py` `91%`、
`ruff check` + `format --check` 全清、`mypy src tools` 0 error。
